# VeryGood 插件开发文档

> 面向想给 VeryGood 写插件、扩展主题能力的开发者。
> 版本：v1.5.0（插件系统完善稳定；v1.4.2 rightbar 注入点移至「近期文章」之后；v1.4.0 新增 rightbar 注入点 + 内置 whisper 时钟微语插件示范 + 站点数据三级降级统计；v1.3.0 目录式插件 + 静态资源 + 元信息 + 禁用开关 + 新注入点）
> 配套命令：`python -m verygood plugins`（列出当前启用的插件清单，不执行插件代码）

---

## 1. 插件能做什么

插件是给主题"加功能"的合法入口，**不需要改主题源码**。一个插件可以：

| 能力 | 场景举例 |
| --- | --- |
| **短代码** `register_shortcode` | 文章里写 `{{< bili BV1xx >}}` 就嵌入 B 站视频 |
| **钩子** `hook` | 文章解析完自动算字数、统计标签、改写内容 |
| **模板注入** `inject` | 往 `<head>` 加统计脚本、往侧栏加组件、往正文前加横幅 |
| **全局变量** `add_global` | 让所有模板直接用 `{{ build_year }}` |
| **过滤器** `add_filter` | 模板里 `{{ text | reading_time }}` 直接用 |
| **静态资源** `static/`（v1.3.0） | 插件自带 CSS/JS，构建时自动拷到 `dist/plugins/{插件名}/` |
| **元信息** `__title__` 等（v1.3.0） | `python -m verygood plugins` 清单展示插件的名称/描述/版本/作者 |

插件是"可插拔"的：删掉插件目录即失效，不会留下任何残骸；`serve` 会监听 `plugins/` 目录变化自动重建。

> 插件加载失败、钩子抛异常都不影响整站构建（错误隔离），但会打印日志，`serve` 时请留意控制台。

> **v1.5.0 新增字段**：`post_parsed` 钩子的 `post` 对象新增 `pin`（布尔值，置顶标记）和 `slug`（字符串，自动拼音 URL，如 `ni-hao`）字段，插件可直接读取或修改。`site_ready` 钩子的 `site` 对象新增 `pinned_posts`（置顶文章列表，已按置顶优先排序）。

## 2. 快速开始（1 分钟写第一个插件）

在仓库根目录建 `plugins/`，放一个插件：

```
plugins/
└── my-first-plugin/
    └── plugin.py
```

```python
# plugins/my-first-plugin/plugin.py
def setup(ctx):                         # 唯一必须的入口
    ctx.add_global("build_year", 2026)  # 模板里直接 {{ build_year }}

    def greet(args):                    # 短代码：文章里写 {{< greet 世界 >}}
        name = args[0] if args else "朋友"
        return f'<b>你好，{name}！</b>'

    ctx.register_shortcode("greet", greet)
```

保存即自动生效（`serve` 会自动重建，手动构建则跑 `python -m verygood build`）。

**三种启用方式（任选其一）：**

1. **自动发现（推荐）**：放进仓库根 `plugins/` 下的子目录（`xxx/plugin.py`）或单文件（`xxx.py`，下划线开头忽略）——零配置即装即用；
2. **显式声明**：`config.yml` 里写 `plugins: ["plugins/my-plugin"]`（相对仓库根的目录名，取目录内 `plugin.py`）；
3. **内置插件**：`verygood/plugins/*.py` 或 `verygood/plugins/*/plugin.py`（随主题发布，见第 5 节）。

**禁用插件（v1.3.0）**：`config.yml` 里写 `plugins_disabled: ["插件名"]`（内置插件名或仓库 `plugins/` 目录名，如 `["site-stats", "footer-note"]`），构建时跳过该插件；`python -m verygood plugins` 会标记「已禁用」。

## 3. API 参考（PluginContext）

`setup(ctx)` 收到的 `ctx` 提供以下方法：

### 3.1 `register_shortcode(name, fn)`

注册文章 Markdown 短代码：正文里写 `{{< name 参数1 参数2 >}}`。

- `fn(args)`：`args` 是**字符串列表**（按空白切分，无参数时为空列表 `[]`）；
- 返回 `str`（HTML 片段）会被原样嵌入；返回 `None`（或不抛异常地失败）则**保留原文本不动**；
- 短代码在 `<pre>` 代码块内不处理；支持 Markdown 转义形态（`{{&lt; name ... &gt;}}` 同样匹配）；
- 例：内置 `{{< youtube dQw4w9WgXcQ >}}`、`{{< bilibili BV1xx411c7mD >}}`。

### 3.2 `hook(name)`（装饰器）

注册构建钩子，在构建流程的关键节点拿到数据：

```python
@ctx.hook("post_parsed")
def _(post):            # 每篇文章解析完
    post["word_count"] = 123   # 改字段，模板即可用 post.word_count
```

### 3.3 `inject(position, html)`

向指定模板位置**追加**一段 HTML：

| 位置 | 含义 |
| --- | --- |
| `head` | `<head>` 末尾（统计脚本、meta 等） |
| `header_extra` | 页头之后 |
| `footer_extra` | 页脚（底部栏）内追加 |
| `body_end` | `</body>` 前（百度推送等脚本） |
| `sidebar_data` | 左侧栏（品牌区与导航之间，v1.3.0；内置插件 site-stats 就在这里；v1.5.0 起座右铭/个性签名展示区紧跟其后） |
| `content_top` | 主内容区最上方（v1.3.0） |
| `content_bottom` | 主内容区最底部（v1.3.0，正文之后、评论之前） |
| `rightbar` | 右栏组件列表（v1.4.0 新增；v1.4.2 起紧跟「近期文章」之后，不再垫底；内置插件 whisper 就在此注入时间卡片与微语卡片） |

**`__BASE__` 占位符（v1.3.0）**：注入内容里的 `__BASE__` 会在渲染时自动替换为站点 basePath（如 `/VeryGood`；无 basePath 时替换为空串）。引用插件静态资源时请用它：

```python
ctx.inject("head", '<link rel="stylesheet" href="__BASE__/plugins/my-plugin/widget.css">')
```

渲染结果：部署在 `https://你.github.io/VeryGood/` 时变为 `/VeryGood/plugins/my-plugin/widget.css`，本机无 basePath 时变为 `/plugins/my-plugin/widget.css`——无需关心站点部署在哪一层。

位置写错会被忽略并打印日志（可用位置：head / header_extra / footer_extra / body_end / sidebar_data / content_top / content_bottom / rightbar）。

### 3.4 `add_global(name, value)`（v1.2.0）

向**全部模板**注入一个 Jinja 全局变量：`{{ build_year }}` 直接用。
同名覆盖规则：插件注入的全局变量优先于内置同名（不会覆盖 `url_for`/`abs_url` 等核心工具）。

### 3.5 `add_filter(name, fn)`（v1.2.0）

注册 Jinja 过滤器：`{{ "一段文字" | wc }}` 直接用 `fn(value)` 的返回值。
例：`ctx.add_filter("wc", len)` 后，模板里 `{{ post.excerpt | wc }}` 就是字数。

> 安全提示：`add_global` / `add_filter` 注入的是构建期 Python 对象，模板渲染时执行。只在**你自己的仓库**启用插件，不要把不可信的第三方插件直接放进 `plugins/`。

### 3.6 钩子清单（完整）

| 钩子 | 时机 | payload 关键字段 |
| --- | --- | --- |
| `init` | 构建初始化，插件加载完、读内容前 | `cfg`（完整配置 dict，可修改） |
| `post_parsed` | 每篇文章解析完 | `post`：url/title/date/tags/category/body_html/reading_time(内置于)/pin(置顶)/slug(拼音自动生成)... |
| `page_parsed` | 每个独立页解析完 | `page` |
| `site_ready` | 站点模型聚合完、渲染前 | `site`：posts/pages/tags/categories/recent... |
| `tpl_context` | 每个模板渲染前（v1.3.0） | `{"template": 模板文件名, "ctx": 渲染上下文 dict}`——往 `ctx` 里加键即可让该模板用到 |
| `finalize` | 全部文件输出后 | `{"out": Path(输出目录), "site": site, "cfg": cfg}` |

`post` / `page` / `site` 都是普通 dict，**改字段即改模板可见数据**（`post["xxx"] = ...` → 模板 `post.xxx`）。`tpl_context` 的 `payload["ctx"]` 就是渲染关键字参数 dict，`payload["ctx"]["my_key"] = value` 后对应模板可直接用 `{{ my_key }}`。

### 3.7 元信息（v1.3.0）

插件模块顶层定义四个可选常量，`python -m verygood plugins` 清单会展示：

```python
__title__ = "我的插件"        # 展示名
__description__ = "一句话说明做什么"   # 描述
__version__ = "1.0.0"        # 版本号
__author__ = "你的名字"        # 作者
```

## 4. 实战示例

### 4.1 页脚留言 + 配置联动（footer-note）

仓库自带 `plugins/footer-note/`，演示 `hook('init')` 读配置 + `inject` 注入 + `add_global` + `register_shortcode` 四种能力：

```python
import datetime as _dt

def setup(ctx):
    ctx.add_global("build_year", _dt.date.today().year)

    def _bili(uin: str = "1"):
        return f'<a href="https://space.bilibili.com/{uin}" rel="noopener" target="_blank">我的 B 站</a>'
    ctx.register_shortcode("bili", _bili)

    @ctx.hook("init")
    def _watch_init(cfg):
        note = ((cfg.get("site") or {}).get("footer") or {}).get("plugin_note", "")
        if not note:
            return
        ctx.inject("footer_extra",
                   '<p class="vg-plugin-note" style="margin:10px 0 0;color:var(--ink-faint);font-size:13px">'
                   + note + "</p>")
```

配套配置（可选）：

```yaml
site:
  footer:
    plugin_note: "❤ 用 VeryGood 搭建"   # 留空则不显示
```

### 4.2 文章字数统计（post-stats）

仓库自带 `plugins/post-stats/`，演示 `hook('post_parsed')` + `add_filter`：

```python
import math, re

_CN = re.compile(r"[\u4e00-\u9fff]")

def _count_words(text: str) -> int:          # 中文按字、其余按词
    if not text:
        return 0
    cn = len(_CN.findall(text))
    return cn + len(_CN.sub("", text).split())

def setup(ctx):
    def reading_time(text: str, wpm: int = 200) -> str:
        return f"约 {max(1, math.ceil(_count_words(text) / wpm))} 分钟"
    ctx.add_filter("reading_time", reading_time)
    ctx.add_filter("wc", _count_words)

    @ctx.hook("post_parsed")
    def _attach_stats(post):
        post["word_count"] = _count_words(post.get("content") or post.get("excerpt") or "")
```

### 4.3 批量标签（改站点模型）

```python
def setup(ctx):
    @ctx.hook("site_ready")
    def _(site):
        for p in site["posts"]:
            p["tags"].append("all")   # 每篇文章都加一个标签
```

### 4.4 目录式插件 + 静态资源 + 元信息（v1.3.0 完整形态）

内置插件 `verygood/plugins/site-stats/` 是 v1.3.0 插件生态的完整示范，结构如下：

```
verygood/plugins/site-stats/
├── plugin.py          # 元信息 + setup(ctx)
└── static/
    ├── site-stats.css # 构建时自动拷到 dist/plugins/site-stats/
    └── site-stats.js
```

```python
# verygood/plugins/site-stats/plugin.py（简化）
__title__ = "站点数据"
__description__ = "侧栏站点数据卡片"
__version__ = "1.0.0"

_STATIC_URL = "__BASE__/plugins/site-stats/"   # 渲染时 __BASE__ → 站点 basePath

def setup(ctx):
    @ctx.hook("site_ready")
    def _inject(site):
        posts = site.get("posts") or []
        ctx.inject("head", f'<link rel="stylesheet" href="{_STATIC_URL}site-stats.css">')
        ctx.inject("sidebar_data", '<section class="side-stats" id="vg-stats">…骨架…</section>')
        ctx.inject("body_end", f'<script src="{_STATIC_URL}site-stats.js" defer></script>')
```

要点：

1. **目录式内置插件**放 `verygood/plugins/{插件名}/plugin.py`，随主题发布即自动启用；用户插件同样支持 `static/`；
2. 构建时该目录的 `static/` 内容被复制到 `dist/plugins/{插件名}/`（构建日志有 `插件静态资源 → plugins/{名}/` 一行）；
3. 引用静态资源一定用 `__BASE__/plugins/{插件名}/...`，任何部署层级都不会 404；
4. 服务端直出渲染骨架数值（如 `f'<b>{len(posts)}</b><span>文章</span>'`），无 JS 也可见；JS 只负责运行时增量。

## 5. 内置插件

随主题发布、自动启用的插件（`verygood/plugins/` 目录内）：

| 插件 | 形态 | 能力 |
| --- | --- | --- |
| `shortcodes.py` | 单文件 | `{{< youtube 视频ID >}}` / `{{< bilibili BV号 >}}` 视频嵌入（iframe 懒加载） |
| `reading_time.py` | 单文件 | 文章 `reading_time` / `word_count` / `reading_note` 字段 |
| `random_post.py` | 单文件 | 生成 `/random/` 随机跳转页（`finalize` 钩子） |
| `site-stats/` | 目录+static | v1.3.0 站点数据组件：**文章数/全站字数服务端直出**，浏览量/访客数不蒜子 → ibruce → localStorage **三级降级真实统计**；v1.4.4 起面板精简为这四个真实可用指标（移除无效的「加载耗时/访客地区」）；`site.sidebar.site_data: false` 关闭 |
| `whisper/` | 目录+static | v1.4.0 右栏时间卡片（`vg-clock`，秒级刷新）+ 打字机微语卡片（`vg-whisper`，逐条轮播、悬停暂停）；`site.rightbar.show_clock` / `show_micro` 开关、`micro_notes` 自定义文案；注入点：`head`（样式）+ `rightbar`（卡片骨架）+ `body_end`（脚本）；**JSON 数据防注入**：`</` 转义为 `<\/` 写入 script 标签，插件侧做同样处理可避免 `</script>` 提前闭合 |

## 6. 调试与排查

```bash
python -m verygood plugins              # 列出：内置 / 自动发现 / 显式配置 / 已禁用，不执行代码
python -m verygood build                # 构建，日志里 [plugin] 行显示每个插件的加载结果
python -m verygood serve                # 改 plugins/ 自动重建；插件报错会打 [plugin] ... 失败 日志
```

常见问题：

| 现象 | 原因 / 解法 |
| --- | --- |
| 插件没被加载 | 检查目录结构：自动发现认 `plugins/名称/plugin.py` 或 `plugins/名称.py`；显式声明认 `config.plugins` 里写的目录 + `plugin.py`；确认没在 `plugins_disabled` 里被禁用 |
| 短代码没展开 | 返回了 `None`；或写在 `<pre>` 代码块里；或拼写与 `register_shortcode` 不一致 |
| 钩子没触发 | 确认钩子名拼写：`init / post_parsed / page_parsed / site_ready / tpl_context / finalize` |
| 静态资源 404 | 检查 `static/` 目录名与 `plugin.py` 同级；注入引用用 `__BASE__/plugins/{插件名}/...`；构建日志确认有 `插件静态资源 → plugins/{名}/` |
| 构建日志出现 `加载失败` | 插件代码异常被隔离，单条报错不影响整站；看堆栈修 `plugin.py` 即可 |
| 单文件内置插件报「相对导入」错误 | v1.3.0 起内置插件统一用文件加载，`from .. import xxx` 会失败；改用绝对导入 `from verygood import xxx` |
| `serve` 改了插件没反应 | 确认保存的是 `plugin.py`（watcher 监听 `plugins/**/*.py`）；还不行就 Ctrl+C 重启 |

## 7. 发布插件（可玩性 / 生态）

想把自己的插件分享出去：

1. 插件目录结构：`plugins/你的插件名/plugin.py` 或 `plugins/你的插件名/plugin.py + static/`（带资源时）+ `README.md`（说明配置项与用法）；
2. 插件入口统一 `setup(ctx)`，**不要** import 主题内部私有函数（`_` 开头的）——公共 API 仅 `PluginContext`；
3. 插件名小写字母、数字、连字符；避免与内置插件（shortcodes / reading_time / random_post / site-stats / whisper）重名；
4. 初始化时读取配置建议用 `hook("init")` 里的 `cfg`，别在模块顶层读（插件加载时配置尚未就绪）；
5. 声明元信息（`__title__` / `__description__` / `__version__` / `__author__`），让 `python -m verygood plugins` 清单可读；
6. 引导用户：把插件目录放进 `plugins/` 即启用，或加入 `config.plugins`；想临时关掉用 `plugins_disabled: ["你的插件名"]`。

> 生态约定：VeryGood 插件彼此独立、可自由组合；请勿在插件里修改或删除页脚品牌署名（`Powered by TechSauce & VeryGood` 受**三层防线**保护：(1) `builder.py` 构建期字符级 + 双指纹校验，篡改则部署失败；(2) `base.html` 内联 footer JS 守卫，DOM 级删除/替换检测；(3) `main.js` 全局 `body` `MutationObserver`，footer 被删时自动重建署名）。
