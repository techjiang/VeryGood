# VeryGood 开发文档

> 面向想要改主题、写插件、研究构建原理、或给 VeryGood 提 PR 的开发者。
> 版本：v1.2.0（2026-08，顶栏锁定 · 分类独立页 · 文章路径定制 · 友链圆形头像 · 署名双层防护 · 插件系统上线）
> 写插件请看专门的 **[插件开发文档](./插件开发文档.md)**；本文侧重构建原理与主题开发。

## 1. 总体架构

```
┌─────────────┐    Issue 事件     ┌──────────────────┐   Markdown    ┌────────────┐
│ GitHub Issue │ ───────────────► │ sync_issues.py    │ ───────────► │ source/    │
└─────────────┘      标签状态机    │（Action 内运行）    │              │ posts,pages│
                                  └──────────────────┘              └─────┬──────┘
                                                                          ▼
┌────────────┐   纯静态 HTML ────  ┌────────────────┐   Jinja2 + Markdown
│ dist/      │ ◄────────────────── │ verygood 构建器 │ ◄────────────────  config.yml
└────────────┘                     └───────┬────────┘                     ▲
    ▲                                      │ 插件钩子                      │
    │      upload-pages-artifact           ▼                               │
┌───┴─────────┐  ┌─────────────────────────────────┐                      │
│ GitHub Pages│◄─┤ build.yml (Actions 工作流)      │ ◄─────────────────────┘
└─────────────┘  └─────────────────────────────────┘
```

- **源**：文章可来自 `source/posts/*.md`（手写），也可来自 GitHub Issue（通过 `scripts/sync_issues.py` 同步生成）。
- **构建**：`python -m verygood build` 读 `config.yml` + `source/` + 主题，产出纯静态站点到 `dist/`。
- **部署**：`.github/workflows/build.yml` 里完成「同步 Issues → 构建 → upload artifact → deploy Pages」全链路。

构建器**零第三方服务依赖**，纯 Python（标准库 + Jinja2 + PyYAML + Markdown + Pygments），一次构建输出整个站点，部署后不依赖任何后端。

### 2.1 config.py：配置规整

- `load_config(path)` → dict；缺失字段用默认值补齐，并对 v1.1 新字段（announcement / rightbar / sidebar / taxonomies / board）做结构规整，保证模板方访问永不 KeyError。
- 特殊键：`theme.root`（主题绝对路径）与 `site.cfg`（原始配置）注入，供模板与插件使用。

### 2.2 mdrender.py：渲染管线

1. Python-Markdown 渲染，启用扩展：`fenced_code / codehilite / tables / footnotes / attr_list / def_list / sane_lists / toc`；
2. 短代码展开：`{{< name arg1 arg2 >}}` 形态（同时兼容 Markdown 转义后的 `{{&lt;` 形态）；`<pre>` 代码块内不处理；
3. 图片懒加载：`<img loading="lazy" decoding="async">` 自动附加（已有 `loading` 时只补 `decoding`）；
4. 目录抽取：`toc_tokens` → 导航树（文章页右栏 TOC 与窄屏折叠目录共用）。

### 2.3 builder.py：核心流程

```
build()
 ├─ 1. load_plugins(cfg)          # 内置 + 用户插件，得 PluginContext(ctx)
 ├─ 2. ctx.emit("init", cfg)      # 插件可在此改配置
 ├─ 3. 读取 content：posts / pages / moments（front matter → 解析 → 渲染）
 ├─ 4. 每篇：ctx.emit("post_parsed", post) / ("page_parsed", page)
 ├─ 5. build_site_model：聚合标签/分类/归档/相关推荐/rightbar 数据/置顶排序
 ├─ 6. ctx.emit("site_ready", site)
 ├─ 7. 渲染全部模板（Jinja2，注入 site 模型、插件 injections）
 ├─ 8. SEO 输出：sitemap / rss / robots / humans（见 seo.py）
 ├─ 9. 拷贝静态资源（主题 static/ + source/assets）
├─ 10. 品牌署名防删除校验（v1.2.0 双层防护）：
 │   构建层（v1.1.8 三层 + v1.2.0 强化）：所有 out/*.html 必须
 │        ① 含 `vg-power-51f3a8` marker；② 可见文本 "Powered by TechSauce
 │        & VeryGood" 逐字符比对（先剥离零宽/双向控制字符再比）；
 │        ③ `<a>` 精确校验：A 链接 netloc = docs.asoe.cn、B 链接 netloc =
 │        github.com 且路径前缀 /techjiang/VeryGood，均须 target=_blank、
 │        rel 含 noopener；分毫不能改——任一失败即 raise（→ Actions
 │        部署失败），删除/改名/改字/偷换链接/加零宽字符均拦截
 │   运行时（v1.2.0 新增）：base.html 注入守卫 JS——每 6s 周期自检 +
 │        MutationObserver 监听署名元素 + 可见性检查（fontSize/clip）
 │        + 零宽字符剥离比较；缺失即整页标记不可用。绕过构建层的
 │        改动也会被运行时兜住
 ├─ 11. ctx.emit("finalize", {...})    # 如 /random/
 └─ 12. 输出统计（文章数/页面/动态数/文件列表）
```

- **置顶排序**：`_sort_meta()` 依据 front matter 的 `sticky`（大顶序）或 `taxonomies` 的 `pin`。
- **分页**：首页与归档按 `posts.per_page` 分页；第 2+ 页加 `noindex`。
- **标签 / 分类 URL（v1.1.5）**：`_tax_slug()` / `tax_path()` 把标签名中的空白折叠为 `-`，URL 与磁盘目录统一用 slug，杜绝未编码空格（RFC 3986 不允许，属 SEO 缺陷；与 `scripts/sync_issues.py::sanitize_tag` 保持一致）。
- **文章 URL 定制（v1.2.0）**：`content.py::parse_post_file` 按优先级 `front matter path`（完整直达，忽略 slug）> `front matter dir`（目录前缀 + slug）> `config.posts.article_dir`（全局默认前缀，默认 `article`）拼 URL；路径自动过 basePath，canonical/sitemap/相关链接全部跟随。
- **分类独立页（v1.2.0）**：`/categories/index.html` 由 `categories.html` 渲染（聚合全部分类卡片），标签总览 `/tags/` 类似；页脚默认导航加入分类入口（`_DEFAULT_FOOTER_NAV`）。
- **动态路由**：`cfg.board.enabled` 为 true 时渲染 `/board/`（服务端渲染 `site.moments` 时间线）。
- **强删目录**：`_rmtree_force()` 处理 Windows 只读文件（`os.chmod(S_IWRITE)` + `onerror` 递归重试），修复 `[WinError 145] 目录不是空的`。

### 2.4 seo.py：SEO 全套

| 产物 | 内容 |
| --- | --- |
| `sitemap.xml` | 首页(priority 1.0/daily)、文章、独立页、标签、分类、归档、留言板、搜索页；带 `xmlns:image` 命名空间，输出每篇文章去重后的图片 `image:image`（供 Google 图片搜索） |
| `rss.xml` | 全量文章（title/link/description/pubDate/guid + dc:creator） |
| `robots.txt` | 允许全部 + 页面第 2+ 页块 + sitemap 声明 |
| `humans.txt` | 作者与站点元信息 |
| 每页 `<head>` | title / description / canonical / OG / Twitter / `application/ld+json`（BlogPosting 或 BreadcrumbList 或 WebSite+SearchAction / ItemList 分页） |

百度收录：`seo.baidu_push` 为 true 时，在 body_end 注入百度主动推送脚本钩子（配合站长平台 token 使用）。

## 4. 插件系统

> 完整 API、钩子清单、实战示例与发布规范见 **[插件开发文档](./插件开发文档.md)**；本节是构建器视角的概要。

### 4.1 加载顺序

1. **内置插件**：`verygood/plugins/*.py`（包内自动发现）；
2. **用户插件自动发现**：仓库根 `plugins/` 下任意子目录的 `plugin.py`，或任意 `xxx.py` 单文件（下划线开头忽略）——**零配置即装即用**；
3. **显式声明**：`config.plugins: ["plugins/my-plugin"]`（相对仓库根，取目录内 plugin.py）。

路径按 `resolve()` 去重；任何插件加载失败或钩子抛异常都**只记日志、不阻断构建**（错误隔离）。`python -m verygood plugins` 可随时列出三种来源的插件清单（`verygood/plugins/__init__.py::list_plugins`，不执行插件代码）。

### 4.2 API（v1.2.0 完整）

```python
# plugins/my-plugin/plugin.py
def setup(ctx):                 # 必须实现的入口
    # 短代码：正文 {{< name arg1 arg2 >}}  →  fn(args) 返回 HTML 字符串，返回 None 保留原文
    ctx.register_shortcode("name", lambda args: "<b>%s</b>" % args[0] if args else None)

    # 钩子（装饰器）：
    @ctx.hook("post_parsed")
    def _(post): ...            # post dict，可加字段供模板用

    # 模板注入：
    ctx.inject("head", "<meta name='x' content='1'>")
    # 位置可选：head / header_extra / footer_extra / body_end

    # v1.2.0 新增——向模板暴露能力：
    ctx.add_global("build_year", 2026)          # 模板 {{ build_year }}
    ctx.add_filter("wc", lambda s: len(s))      # 模板 {{ text | wc }}
```

- `ctx.globals` / `ctx.filters` 在 `builder.py` 渲染前并入 `env.globals` / `env.filters`（插件同名全局优先于内置非核心键）；
- `hook` 的完整清单见 [插件开发文档](./插件开发文档.md) 3.6；`builder.py` 中五个 `ctx.emit(...)` 触发点分别位于：`init`（读内容前）、`post_parsed` / `page_parsed`（每篇解析后）、`site_ready`（模型聚合后）、`finalize`（输出完成后）。

### 4.3 钩子清单

| 钩子 | 时机 | payload 关键字段 |
| --- | --- | --- |
| `init` | 构建初始化 | `cfg` |
| `post_parsed` | 每篇文章解析完 | `post`：url/title/date/tags/category/body_html/reading_time(内置)... |
| `page_parsed` | 每个页面解析完 | `page` |
| `site_ready` | 站点模型就绪 | `site`：posts/pages/tags/categories/recent 等 |
| `finalize` | 全部输出前（dist 已建） | `{"out": Path, "site": site, "cfg": cfg}` |

### 4.4 示例：批量标签

```python
def setup(ctx):
    @ctx.hook("site_ready")
    def _(site):
        for p in site["posts"]:
            p["tags"].append("all")
```

## 5. Issue 同步链路（sync_issues.py）

`.github/workflows/build.yml` 触发条件：

```yaml
on:
  push:
    branches: [main, master]
    paths-ignore: [README.md, LICENSE, .gitignore]  # 纯文档提交不触发
  issues:
    types: [opened, edited, reopened, closed, labeled, unlabeled, deleted]
  workflow_dispatch: {}                             # 手动触发
```

`scripts/sync_issues.py` 逻辑：

1. `gh issue list` **分页拉取**全部 Issue（每页 100，最多 50 页，防截断）；
2. 对每个 Issue 判定：
   - 打标签 `Article` → `source/posts/issue-{N}.md`（front matter：title/date/updated/tags/category/sticky-yaml 保留块）；
   - 打标签 `Draft` → 同目录但标记 draft（线上不构建）；
   - 打标签 `Page` → `source/pages/issue-{N}.md`；
   - 打标签 `Moment` → `source/moments/issue-{N}.md`（朋友圈动态，渲染到 `/board/` 时间线，正文支持图片/表情）；
   - **无发布/草稿/页面/动态标签的普通 Issue → 跳过**（仅用于讨论，避免误发布）；
3. Issue 关闭/删除 → 删除对应 md（关闭即下线）；
4. 其余 label → tags；`分类:` / `category:` 前缀 → category（兼容中英文冒号）；
5. 标签先经 `sanitize_tag()` 清洗：空白折叠为 `-`（与构建器 `_tax_slug` 对齐，保证 URL slug 一致），中文等非 ASCII 保留原样；
6. 依赖 `GH_TOKEN`（GITHUB_TOKEN 自动注入）；可用 secret `VG_PUBLISH_LABEL` 覆盖发布标签；Moment 记录落盘为 `source/moments/issue-{N}.md`，构建时按更新时间倒序渲染到 `/board/` 时间线；
7. 可用 `VERYGOOD_GH` 环境变量注入 `gh` 命令路径（如 `VERYGOOD_GH="python fake_gh.py"`），在不联网/无 token 的本地复现整条状态机做回归测试。

## 6. GitHub Actions 工作流要点

- 权限最小化：`contents: read / pages: write / id-token: write`；
- `concurrency: pages` + `cancel-in-progress` 防止同一时间多个构建互踩；
- Python 3.12 + pip 缓存；无需额外服务；
- `upload-pages-artifact` 直接上传 `dist/`，`deploy-pages` 部署；
- 手动触发：Actions → Run workflow（`workflow_dispatch`）。

### 本地复现 CI


## 8. 给主题写样式时的约定

- 字符卫生：源码一律 ASCII 半角标点；html 模板内中文文案无碍；
- CSS 命名：BEM 简化（`.side-widget__title`、`.post-toc__list`）；v1.x 区块统一在 main.css 末尾追加并注释版本；
- 断点变量：`--content-w: 1300px; --article-w: 780px; --rightbar-w: 330px`；
- 移动端顶栏占位：任何新增的 fixed 顶栏必须像 header 一样用 JS 实测高度写入 `--vg-header-h` 并给 body `padding-top`，不要写死像素；
- JS 错误隔离：灯箱/回顶等模块各自 try/catch，单项失败不影响整页；署名守卫不隔离（缺失即整页失效）；
- localStorage 键统一前缀：`vg-`。

## 10. 常见坑

| 现象 | 原因 / 解法 |
| --- | --- |
| `[WinError 145] 目录不是空的` | 旧 dist 只读文件；builder 已用 `_rmtree_force` 兜底，勿改回裸 `rmtree` |
| 模板注释报 `Missing end of comment tag` | Jinja 注释是 `{# ... #}`，别写成 `<!-- ... -->` 混用 |
| 右栏不显示 | main.css 中 `.rightbar{display:none}` 级联优先级覆盖了 1366px 的 flex；已修复并在 v1.1 块追加同权重复声明 |
| 相关推荐变量串台 | 模板中 `{% set post = r %}` 会污染外层；用 `{% with post = r %}` |
| Edge 无头截图最小视口 756px | `--window-size` 小于 860 会被钳制，移动端验收请直接截 756 宽 |
| 插件 API 记错 | 旧版文档写的 `register/ctx.shortcode/ctx.on` 已废弃；统一为 `setup(ctx)` + `register_shortcode` / `@ctx.hook` / `inject` / `add_global` / `add_filter` |
| 移动端顶栏把内容顶掉一块 | 加了固定头部但没写 `--vg-header-h` + `padding-top` 占位；参考 `main.js::measureHeader()` 与 `base.html` body 样式 |
| 文章自定义 path 后旧链接 404 | `path` 优先级最高、直达指定路径，改路径旧链接即失效；协同 `dir` / `article_dir` 做好规划 |
| 友链头像被拉伸变形 | 头像容器必须 `object-fit: cover` + `border-radius: 50%` + 白/深灰底（透明底 logo 也兼容）；勿改回 `contain` |
| 构建失败 `Missing vg-power marker` / `品牌署名保护触发` | 页脚署名被改/删、偷换链接或混入零宽字符（构建层三层+剥零宽校验触发）；恢复原样 `Powered by TechSauce & VeryGood` + `vg-power-51f3a8` 标记 |
| `verygood serve` 资源 404（basePath 非空时） | 本地预览 handler 需在 `translate_path` 剥离 `_bp` 前缀再映射 dist（v1.1.8 已修）；勿直接用裸路径 |
| 页面整页变灰不可用 | 运行时署名守卫（main.js）检测到缺失品牌标记；恢复 footer 标记即可 |
