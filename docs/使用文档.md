## 1. 什么是 VeryGood

VeryGood 是一个跑在 **GitHub Pages** 上的开源博客主题：

- **写文章**：不用碰代码、不用拉仓库——直接在 GitHub 的 **Issue 里写 Markdown**，打一个 `Article` 标签，文章就自动上线。
- **改样子**：不换主题不用求人——一个 `config.yml` 就能管住站名、公告、侧栏、右栏、友链、评论、SEO。
- **个性化**：侧栏内容、分类/标签描述、友链头像、公告、朋友圈动态……都能自己加。
- **免费且稳定**：Pages + Actions 全部由 GitHub 免费提供；构建是一次性的本地 Python 脚本，不依赖任何第三方服务。

## 2. 部署步骤（第一次）

### 2.1 创建自己的仓库

1. 打开 VeryGood 的 GitHub 仓库，点 **Use this template → Create a new repository**；
2. 仓库名建议填 **`你的用户名.github.io`**（这样站点地址就是这个域名）；
3. 创建完成后，这个仓库就是你的博客仓库。

> 提示：仓库创建后里面自带的 5 篇示例文章（`source/posts/issue-*.md`）可以先删掉，避免和你的内容混在一起。

### 2.2 修改配置

网页上直接改 `config.yml`（点铅笔图标编辑）最省事。**至少改这三处**：

```yaml
site:
  title: 我的博客          # 站点名（显示在侧栏与标题栏）
  url: https://你的用户名.github.io   # 你的真实站点地址，不要带末尾斜杠
author:
  name: 你的名字          # 侧栏头像旁显示的名字
```

顺带可以改：`site.subtitle`（副标题）、`author.avatar`（头像图 URL）、`author.bio`（一句话介绍）、`links`（你的友链列表）。

改完点 **Commit changes**，会自动触发一次构建。

### 2.3 开启 GitHub Pages

仓库 **Settings → Pages**：

- **Source** 选择 **GitHub Actions**（不要选 Branch）；
- 保存后等第一次 Actions 跑完（Actions 页能看到 `Deploy VeryGood Blog` 工作流）；
- 打开 `https://你的用户名.github.io` 就能看到你的博客了。

> 若提示 DNS/证书未生效，通常等 1~2 分钟即可。

## 3. 写文章（Issue 即文章）

### 3.1 发布一篇

1. 仓库 **Issues → New issue**；
2. 正文写 Markdown（支持标题、列表、代码块、表格、图片、脚注等完整语法）；
3. 右侧 **Labels** 勾选 **`Article`**（必须）；
4. 点 **Create**，等 Actions 构建完成即可看到新文章。

### 3.2 标签即状态机

| 标签 | 效果 |
| --- | --- |
| `Article` | 发布文章（标签名可在 `config.yml issues.publish_label` 改） |
| `Draft` | 草稿，线上不可见；本地 `python -m verygood build --drafts` 可预览 |
| `Page` | 独立页面（比如「关于我」），不进入文章流 |
| `Moment` | 朋友圈动态，展示在 `/board/` 时间线（详见 4.7） |
| `分类:xxx` | 归入分类 xxx（兼容 `category:xxx` / `Category:xxx`） |
| 任意标签 | 自动成为文章的 tag，进标签页/标签云 |
| 无这些标签 | 不发布、不同步（普通 Issue 仅用于讨论） |

### 3.3 状态流转

- **关闭 Issue** → 文章从站点下线（同名 `source/posts/issue-N.md` 被自动删除）；
- **重新打开** → 文章恢复上线；
- **编辑正文** → 内容自动更新；
- **改标签** → 分类/标签自动变化。

### 3.4 在 Issue 里插入图片/视频

- **图片**：直接把图片拖进 Issue 文本框，GitHub 会上传到 `user-images.githubusercontent.com` 并插入 Markdown。发布后正文里点击图片可看**灯箱大图**（支持键盘左右切换同一篇文章的图片、ESC 关闭）。
- **视频**（YouTube / B 站），写短代码：

```markdown
{{< youtube dQw4w9WgXcQ >}}
{{< bilibili BV1xx411c7mD >}}
```

### 3.5 文章访问路径自定义（v1.2.0）

文章 URL 默认是 `/article/{标题slug}/`，你可以用三种方式改：

**① front matter `path`（最灵活，直达指定路径）**

```markdown
---
path: /abc          # 文章就变成了 域名/abc
---
```

```markdown
---
path: /wz/abc       # 子路径同理：域名/wz/abc
---
```

**② front matter `dir`（只改前缀，保留标题 slug）**

```markdown
---
dir: /notes         # 文章变成 域名/notes/{标题slug}/
---
```

**③ config 全局设置 `posts.article_dir`（默认前缀换成你喜欢的）**

```yaml
posts:
  article_dir: blog   # 所有文章默认变成 域名/blog/{标题slug}/
```

优先级：`path` > `dir` > `article_dir`（默认 `article`）。改路径后旧链接会失效，建议在旧文章里更新前用 `serve` 预览确认。

> 路径会**自动拼上 basePath**：子路径部署时（如 `https://user.github.io/repo/`）写 `path: /abc`，最终访问是 `https://user.github.io/repo/abc/`，不用自己加前缀。

### 3.6 给文章设置封面（v1.1.7）

封面会自动出现在：**首页文章卡片**、**文章页顶部**、社交分享图（og:image，微信/微博/推特转发时显示的那张大图）、sitemap 图片与 JSON-LD 结构化数据里。

**写法 A（推荐，Issue 即文章时）**：在 Issue 正文的**最开头**写一段 front matter 指令块，Actions 同步时会自动识别并剥离，不会出现在正文中：

```markdown
---
cover: https://example.com/cover.png
cover_alt: 封面描述文字
summary: 这段文字会成为文章摘要（不写则自动截取正文）
---

这里是文章真正的正文……
```

**写法 B（推送 Markdown 时）**：在 `source/posts/*.md` 文件头部写 front matter：

```markdown
---
title: 我的文章标题
cover: /assets/my-cover.png   # 站内路径：图片放 source/assets/ 会发布到 /assets/
cover_alt: 封面描述
---
```

**规则与建议**：
- `cover` 填**外链 URL** 或**站内相对路径**（如 `/assets/xxx.png`）都可以，自动处理子路径前缀，不会拼错；
- 所有文章都不写封面时，可用配置 `posts.cover_default` 给一个统一兜底图；
- 建议图片 **1200×630（16:9）**、**≤300KB**、png/jpg/webp 皆可，加载更快也更好看；
- 不填 `cover` 就是「无封面卡片」，首页卡片会显示粉色描边样式，同样美观。

**封面展示效果（v1.4.0 升级）**：
- **文章页**：封面与标题**融合**——封面作为整块背景，标题/分类/发布时间覆于其上，向下渐变过渡到正文底色，视觉上浑然一体（无封面时保持传统的标题置顶样式）；
- **首页文章卡片**：封面底部带**柔和渐变遮罩**，卡片更精致；
- 文章页的分类（如「博客」「技术」）展示位置调整到了**标题正下方**，不再孤立在顶部。

### 3.7 文章页底部信息（v1.1.7，可配置）

文章读完后自动展示（都可在 `config.yml → site.post_extra` 关闭）：

- **更新于**：文章有修改记录时，标题下会显示「更新」时间（比发布日期晚）；
- **版权行**：本文作者 + 原文链接；
- **分享栏**：一键分享到 微博 / X(Twitter) / LinkedIn，或复制链接（点击显示「已复制」）。

## 4. 配置详解（config.yml 全字段）

### 4.1 站点基础

```yaml
site:
  title: 我的博客
  subtitle: 记录日常与代码
  description: 一句话给搜索引擎看的站点描述
  keywords: [博客, 生活]        # 可省略
  url: https://you.github.io    # 必填
  basePath: ""                  # 部署在 https://user.github.io/repo/ 时填 repo
  language: zh-CN
  timezone: Asia/Shanghai
  footer_text: "© 2026 我"       # 页脚自定义文字（默认隐藏版权行，可留空）
```

> 注意：`basePath` 只在子路径部署时需要，`你的用户名.github.io` 这种根域名部署一律留空。

### 4.2 底部栏（v1.1.8，可自定义）

**版权行与品牌署名行是字符级锁定的**——`© 年份 标题 …` 与 `Powered by TechSauce & VeryGood` 的内容分毫不能改：删除、改名、改字或偷换链接都会让**构建失败（部署即断）**。v1.3.0 起该防护升级为**双指纹机制**：构建层为署名行计算 SHA-256 指纹嵌入页面（`data-vg-fp`/`data-vg-sig`），并对署名文本与链接做字符级比对，任何改动直接让构建抛错。v1.4.2 继续加固：构建层强制 **site-footer 全页唯一**、指纹 marker 必须位于 footer 块内部（防搬到别处糊弄）、署名行全页唯一、两个链接**与文本一一配对**（TechSauce → docs.asoe.cn 在前，VeryGood → github.com/techjiang/VeryGood 在后，禁止交错调包）。即使有人绕过构建层，页面**运行时守卫**（签名重算比对 + DOM 变化监听 + 可见性遮挡探测，随机 3~9 秒周期自检；v1.4.0 起公告弹窗/图片灯箱已加入遮挡白名单并增加二次确认，防误杀）也会立即让整页变为不可用，这是本主题的品牌保护条款，不可关闭、不可绕过。可自定义的只有署名行之上的**两栏内容**：左栏「探索」导航（`site.footer.nav`）、右栏「关于」简介（`site.footer.about`）：

```yaml
site:
  footer:
    about: "VeryGood\n粉色 · 极简 · 属于 GitHub Pages 的博客"  # 底部右栏「关于」简介（多行用 \n，单引号双引号写法都支持）
    nav:                                    # 底部左栏「探索」导航（不写则用默认菜单：首页/归档/标签/动态/GitHub/RSS）
      - label: 首页                         # 菜单名（自由自定义）
        url: /                              # 站内路径写相对路径（自动拼子路径），外链写 http(s)://
        if: ""                              # 可选：board=启用动态页才显示；github=填了 GitHub 地址才显示
        external: false                     # true 时按外链处理（新窗口打开）
      - label: GitHub
        url: https://github.com/{github}    # {github} 自动替换为你的 GitHub 地址
        external: true
```

> 示例：把「动态」改成「留言板」、删掉 RSS、新增一个「关于我」页面入口，都只改 `site.footer.nav` 即可。
>
> **底部栏版式（v1.4.2）**：页脚为简洁两栏——左栏「探索」展示 `site.footer.nav` 导航列表，右栏「关于」展示 `site.footer.about` 简介；之下才是细版权行与品牌署名行。移动端两栏自动纵向堆叠。
>
> **底部栏贴底（v1.4.0）**：分类、标签、动态、友链等短内容页，底部栏会**始终贴在视口底部**（不是"飘"在内容中间）；内容超过一屏时自动随页面滚动，全站所有页面统一生效，无需任何配置。

### 4.3 公告弹窗（v1.1.6）

进入页面后自动弹出的居中小弹窗，可带标题和链接按钮；访客关闭后本浏览器不再弹（localStorage 记忆）。

```yaml
site:
  announcement:
    enabled: true          # 关掉就把这里改 false
    title: "欢迎来到 VeryGood"     # 弹窗标题，留空 "" 则只显示文案
    text: "🎉 新文章已发布"        # 支持少量 HTML，比如 <a href="...">
    link: "/board/"        # 跳转地址：站内页面写相对路径（自动拼 basePath），外链写 http(s):// 开头
    btn_text: "去看看"      # 按钮文案，留空默认「了解更多」
    type: info             # 三种风格：info（粉）/ tip（青）/ warn（橙）
```

> 公告链接是 404 的常见原因：**子路径部署时（如 `/VeryGood/`），站内链接不要写 `https://你的域名/board/`，要写相对路径 `/board/`**——主题会自动拼上 basePath，写完整域名反而会拼错跳 404。

弹窗出现于页面加载约 1 秒后；点右上 ×、ESC 或点击弹窗外区域均可关闭。

### 4.4 左侧栏（v1.1）

左侧栏自上而下固定为：**站点信息（头像+站名+bio）→ 站点数据组件（可选）→ 最近更新（默认关闭）→ 导航 → 自定义模块**。

```yaml
site:
  sidebar:
    recent_count: 0        # 最近更新展示条数；v1.3.0 起默认 0（关闭），避免与右侧「近期文章」重复
    collapse: false        # true 时最近更新默认折叠，访客可点开
    custom:                # 自定义模块：想放什么放什么
      - title: 我的项目
        icon: "⚡"
        html: "<p><a href='https://github.com/me/proj'>Project A</a></p><p>这里写任意 HTML</p>"
      - title: 打赏
        icon: "🎁"
        html: "<p>…</p>"
```

- **站点数据组件（v1.3.0）**：把 `site.sidebar.site_data` 打开（默认即 true，见 4.13），左侧栏会自动出现一张站点数据卡，展示**文章总数、总字数、累计访问、访客数、加载时间、地区**等实时信息（由内置 `site-stats` 插件驱动）。它替代了原先「最近更新」的位置，让左右栏不再内容重复。
- 导航项用 `site.nav` 追加（如友链、关于）；动态入口已内置在导航与页脚。
- 移动端（<861px）左侧栏自动收入汉堡菜单；同时**顶栏固定在最上方不随滚动移动**（v1.2.0，正文自动留出顶栏高度，不会遮挡内容）。

### 4.5 右侧栏（v1.1）

超宽屏（≥1760px）时显示在正文右侧（330px 宽），放置：**文章目录**（文章页）、**近期文章**、**标签云**、**分类**、**友链缩略**、**时间卡片**、**微语卡片**。1760px 以下（含 1440/1680 等常见屏）自动隐藏，正文保持 1360px 满宽不被挤压；更窄的屏改为折叠目录。

```yaml
site:
  rightbar:
    enabled: true
    show_toc: true         # 文章目录放右栏（正文不再被目录挤压）
    show_recent: true
    recent_count: 5        # v1.3.0 起独立管理，不再受左栏 recent_count 影响
    show_tags: true
    tags_max: 24
    show_categories: true
    show_links: true
    links_max: 8
    show_clock: true       # v1.4.0：时间卡片（本地时间，秒级刷新，内置插件 whisper）
    show_micro: true       # v1.4.0：微语卡片（打字机效果逐条轮播）
    micro_notes:           # v1.4.0：自定义微语内容（最多建议 12 条；写 [] 用插件内置文案）
      - "用 Issue 写文章，GitHub Actions 自动构建发布。"
      - "莫兰迪粉：温柔克制，但也很有态度。"
```

> v1.3.0 起左右两栏的「最近文章/最近更新」已**解耦**：右栏「近期文章」默认为 5 条（可用 `rightbar.recent_count` 调），左栏「最近更新」默认关闭（`sidebar.recent_count: 0`），不会再有重复内容。
>
> **时间卡片与微语卡片（v1.4.0，v1.4.2 调整位置）**：由内置 `whisper` 插件提供。时间卡片显示访客本地时间（秒级刷新）；微语卡片以**打字机效果**逐条轮播短句，鼠标悬停可暂停、退出后继续播放。两个卡片均可独立开关，微语内容用 `micro_notes` 自定义。v1.4.2 起这两个卡片**紧跟「近期文章」之后**（顺序：近期文章 → 此刻 → 微语 → 标签云 → 分类 → 友链），不再垫底。

```yaml
author:
  name: 你的名字
  email: you@example.com
  avatar: "https://example.com/avatar.png"   # 留空则不显示头像
  bio: 一句介绍
  social:
    github: yourname
    twitter: ""

```

### 4.7 分类 / 标签的描述与置顶（v1.1）

给分类/标签写介绍、置顶，会在**分类独立页**（`/categories/`，v1.2.0 新增，聚合所有分类卡片）与各分类/标签页展示：

```yaml
taxonomies:
  categories:
    技术:
      desc: 技术相关文章都会放这里
      pin: true            # 置顶：排在分类云前面
    生活:
      desc: 记录生活的碎片
  tags:
    verygood:
      desc: 关于 VeryGood 主题本身的文章
      pin: true
```

> 分类/标签的名字不需要预先声明——**文章里用了就会自动出现**。这里的配置只是为了「加描述」和「排序置顶」。
>
> v1.2.0 起分类有**独立的 `/categories/` 页面**（不再是归档页的一部分），页脚默认导航也加了分类入口；每个分类自己的文章列表页仍在 `/category/{分类名}/`。

### 4.8 朋友圈动态（v1.1.2）

位于 `/board/`：**站长/站点管理者**的朋友圈式动态时间线。动态内容不是访客留言，而是由站长通过 **GitHub Issue + Actions 推送**的碎碎念、站点公告、更新日志等——像发朋友圈，关闭对应 Issue 即下线。

发布一条动态：

1. 在仓库新建 Issue，正文写下动态内容（Markdown，支持图片、视频）；
2. 给 Issue 打上 **`Moment`** 标签；
3. Actions 自动同步为 `source/moments/` 下的文件并部署，页面即时更新。

```yaml
board:
  enabled: true    # false 则不出生成 /board/ 页面
  title: 朋友圈动态
  desc: 页面顶部的介绍文字
  per_page: 30     # 时间线最多展示条数
  repo: ""         # 填 "你的用户名/仓库名"：动态卡片带「Issue #编号」跳转到对应 GitHub Issue；留空不显示
  giscus: false    # 设为 true 时在动态页下方再挂一套 giscus 评论（需要先配置 comments.giscus）
```

> 说明：`Moment` 是 `issues.moment_label` 的默认值，可改名。`Moment` 与 `Article` / `Draft` / `Page` 互斥：打上多个时按 Page > Moment > Draft > Article 取其一。手写 markdown 放到 `source/moments/` 也可以（需要带 front matter，见 `scripts/sync_issues.py` 生成的示例）。

### 4.9 评论（文章页）

> 评论**默认是关闭的**（`provider: none`）。主题已内置 giscus / utterances 两套评论系统，任选其一开启即可，不需要改任何模板。

**giscus（推荐，GitHub Discussions 驱动）**：

1. 打开 [giscus.app](https://giscus.app)；
2. 在「仓库」处填你的仓库（**需先开启仓库的 Discussions**：仓库 Settings → Features → Discussions 打勾）；
3. 按网页引导选择分类、主题，页面会自动生成一段脚本；
4. 从脚本里抄出四项，填到 `config.yml`：

```yaml
comments:
  provider: giscus
  giscus:
    repo: "你的用户名/评论仓库名"
    repo_id: "R_xxx"          # 从 giscus.app 获取
    category: "Announcements"
    category_id: "DIC_xxx"
    mapping: pathname
    lang: zh-CN
```

**utterances（更简单，Issues 驱动）**：只需填 `provider: utterances` 和 `repo`（如 `你的用户名/你的博客仓库`）。

配置完成后，文章页尾部、动态页（`board.giscus: true` 时）都会自动出现评论区。

### 4.10 友链（支持图片头像 v1.1）

`/links/` 页大卡片 + 右栏缩略共用这份数据；头像 v1.2.0 起显示为**圆形**（非方形图片自动 cover 裁剪居中，不拉伸变形）：

```yaml
links:
  - name: GitHub
    url: https://github.com
    desc: 给友链写一句话介绍
    avatar: "https://github.com/github.png"   # 头像图 URL；留空自动显示首字母彩球
  - name: 另一博客
    url: https://example.com
    desc: 纸上得来终觉浅
    # avatar 不填 = 彩球头像（按名字首字符自动配色）
```

> 头像底色为白色（深色模式为深灰）并裁成圆形：带白底/透明背景的 logo（GitHub、B 站等）放上去观感最佳，无需自己先抠图。

### 4.11 文章与 SEO

```yaml
posts:
  per_page: 8            # 首页每页文章数
  excerpt_length: 150    # 摘要字数
  article_dir: article   # 文章默认目录前缀（v1.2.0，可改，见 3.5）

  toc_depth: 2-3         # 目录抓取 h2~h3
  related: 3             # 文章尾部相关推荐条数
  date_format: "%Y-%m-%d"
  cover_default: ""      # 文章没写封面时的兜底封面

# 文章页底部信息（v1.1.7，全部可开关）

seo:
  image: /assets/og-default.png   # 分享到微信/推特时显示的默认图
  twitter_handle: "@xxx"
  google_site_verification: ""    # Google Search Console 验证 token
  baidu_site_verification: ""     # 百度站长验证 token
  baidu_push: false               # 百度主动推送（构建产物带推送脚本）
  sitemap: true                   # sitemap.xml（含首页/文章/页面/标签/分类/归档/动态 + 图片）

  noindex_page_2plus: true        # 分页第 2 页起对搜索引擎 noindex（防重复内容）
```

### 4.12 插件（v1.2.0 生态，v1.3.0 强化）

VeryGood 有完整的**插件系统**：短代码、钩子、模板注入、全局变量、Jinja 过滤器五种能力，不需要改主题代码就能给博客加功能。v1.3.0 起插件系统整体强化：

- **目录式内置插件**：内置插件从分散的 `.py` 文件改为 `verygood/plugins/{插件名}/` 目录结构，可携带自己的 `static/` 静态资源与 `meta` 元信息；
- **静态资源**：插件的 `static/` 目录会自动拷贝到构建产物 `plugins/{插件名}/` 下，模板里用 `{{ __BASE__ }}/plugins/{插件名}/xxx.css` 引用即可（`__BASE__` 在构建时自动替换为正确的子路径前缀）；
- **禁用开关**：`config.yml` 的 `plugins_disabled` 列表可以按名字关掉任何插件（包括内置插件）；
- **新注入点**：新增 `content_top`（文章内容上方）、`content_bottom`（文章内容下方）、`sidebar_data`（左栏站点数据区）三个模板注入点。

**作为使用者**，最省事的方式是**自动发现**：在仓库根建 `plugins/` 目录，把一个插件目录（含 `plugin.py`）放进去就自动加载，零配置：

```
plugins/
└── my-plugin/
    └── plugin.py       # 放进去即生效
```

也可以显式声明（相对仓库根的目录路径）：

```yaml
plugins: ["plugins/my-plugin"]
```

不想用某个插件时（比如不需要站点数据组件），在 `config.yml` 里关掉：

```yaml
plugins_disabled: ["site-stats"]
```

仓库自带示例插件（`plugins/footer-note/` 页脚留言、`plugins/post-stats/` 文章统计），都在 `plugins/` 里即装即用。查看当前插件清单：本地跑 `python -m verygood plugins`。

**内置插件一览（v1.4.0）**：

| 插件 | 位置 | 作用 |
| --- | --- | --- |
| `site-stats` | 内置（目录式） | 站点数据组件：文章数/总字数/浏览量/访客数/加载时间/地区，展示在左栏（需 `site.sidebar.site_data: true`） |
| `whisper` | 内置（目录式） | 右栏时间卡片（秒级刷新）+ 打字机微语卡片（v1.4.0，`site.rightbar.show_clock` / `show_micro` 控制） |
| `shortcodes` | 内置 | `{{< youtube >}}` / `{{< bilibili >}}` 视频嵌入 |
| `reading_time` | 内置 | 自动计算阅读时长与正文字数（`post.reading_time` / `post.word_count`） |
| `random-post` | 内置 | 随机文章跳转（`/random/`） |
| `footer-note` | 示例 | 页脚留言（仓库 `plugins/` 下） |
| `post-stats` | 示例 | 文章统计（仓库 `plugins/` 下） |

> sitemap 收录标签/分类/归档/动态页等路径是主题 SEO 的核心能力（`seo.py`），不依赖插件。

**想自己写插件 / 想分享插件**：见 **[插件开发文档](./插件开发文档.md)**（含 API 参考、钩子清单、三个实战示例、发布规范）——这是 VeryGood 生态的入口。

### 4.13 站点数据组件（v1.3.0）

左栏的站点数据卡片由内置 `site-stats` 插件驱动，展示站点运行数据，默认开启、随时可关：

```yaml
site:
  sidebar:
    site_data: true         # false 即关闭组件（同时可配 plugins_disabled: ["site-stats"] 停用插件）
```

组件展示的信息（v1.4.0 起统计链路真实可用、多级降级）：

- **文章数 / 总字数**：构建期由主题统计（字数取正文净化后的字数，见 [开发文档](./开发文档.md)），服务端直出、无刷新即可见；
- **浏览量 / 访客数**：v1.4.0 起按 **不蒜子 → ibruce → localStorage 三级降级**逐级尝试：有可用第三方统计服务就用其真实数据（不蒜子博客园生态、ibruce 备用），均不可达时自动降级为 localStorage 访客端计数（同浏览器只计一次），**任何网络环境下都有真实数字可统计**，不再出现空白；
- **加载时间**：页面 DOM 加载耗时（毫秒级，异常数据自动显示 `–`）；
- **地区**：根据访客 IP 判断的粗略地区（访客端拉取 IP 属地接口，失败时显示「本地」）。

> 该组件不依赖任何后端，纯静态 + 访客端脚本实现，隐私友好、GitHub Pages 免费额度内可用。不想用第三方统计（不蒜子/ibruce）时，把 `plugins_disabled: ["site-stats"]` 加上即可彻底停用；只想用本地计数可保留组件默认行为。

## 7. 常见问题

**Q：建好仓库后站点打不开？**
先确认 Settings → Pages 的 Source 选了 **GitHub Actions**；再到 Actions 页看工作流是否成功；成功但 404，检查 `site.url` 是否写对、是否多了末尾斜杠。

**Q：发了 Issue 但站点没更新？**
确认标签是 **`Article`** 且拼写一致；确认工作流没排队/失败；Issue 正文为空也可能被跳过。

**Q：草稿怎么看？**
本地 `python -m verygood build --drafts` 后 `serve` 预览。线上不会出现。

**Q：朋友圈动态想加图片/视频？**
直接在 Issue 正文用 Markdown 写 `![alt](图片URL)` 或粘贴视频，Actions 同步后自动出现在时间线卡片里，点图片可放大（灯箱）。

**Q：公告弹窗怎么关？**
`site.announcement.enabled: false`；对单个访客，点弹窗右上 × / ESC / 弹窗外区域，即永久（本浏览器）关闭。

**Q：左栏的「站点数据」卡片显示加载时间/地区异常？**
加载时间由访客浏览器计时，极慢网络或异常环境下会显示 `–` 表示不可用（不会显示错误数字）；地区根据访客 IP 判断，个别网络（如内网/代理）拿不到时显示「本地」，均不影响其它功能。

**Q：代码块右上角的语言标签和复制按钮？**
v1.4.0 起构建期自动为代码块识别语言（如 Bash / Python / YAML），右上角显示语言语法标签和一个**纯图标复制按钮**，点击一键复制整个代码块（提示「已复制」）。无需任何配置，全站自动生效。

**Q：右栏的时间卡片 / 微语卡片不想显示？**
`site.rightbar.show_clock: false` 或 `show_micro: false` 可分别关闭；微语内容用 `micro_notes` 自定义（写 `[]` 恢复插件内置文案）。

**Q：想去掉左栏的「最近更新 / 站点数据」？**
左栏「最近更新」默认已关闭（`sidebar.recent_count: 0`）；「站点数据」设 `site.sidebar.site_data: false` 即消失，或更彻底地在 `plugins_disabled` 里加 `site-stats` 停用整个插件。

**Q：想让别人复制我的主题时也连同自定义一起？**
VeryGood 鼓励 fork 后魔改：主题在 `themes/`、插件在 `plugins/`、配置在 `config.yml`，改完整体推上去即生效。
